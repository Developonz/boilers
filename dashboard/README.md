# Дашборд котлов

Используемая версия сайта: присланные frontend и backend с сохранённой
авторизацией Keycloak и ранее добавленными ускорениями расчёта.

## Файлы

- `backend/main.py` — API сайта и маршруты авторизации.
- `backend/k2_model.py` — загрузка моделей, данных, истории и расчёт показателей.
- `backend/inference_acceleration.py` — ускоренная очистка и ограниченный кэш прогнозов.
- `backend/auth/` — присланная реализация авторизации.
- `backend/.env` — присланные настройки окружения и Keycloak.
- `backend/requirements.txt` — зависимости присланного backend.
- `predictive_maintenance_dashboard/src/` — исходники интерфейса.
- `predictive_maintenance_dashboard/dist/` — собранный интерфейс для браузера.
- `data/boilers.json` — рабочая конфигурация котлов.
- `models/` — место для экспортированных моделей.
- `tests/` — проверки API, моделей, авторизации и ускорения.

## Пути к данным и моделям

Относительные пути в `data/boilers.json` считаются от этой папки `dashboard/`.
После переноса сохранено назначение прежних локальных путей: `../../legacy/`
заменено на `../legacy/`. Дубликат конфига из backend удалён.

Для работы в Docker данные разместите внутри `dashboard/data/`, а модели —
в `dashboard/models/`. В JSON укажите пути `data/...` и `models/...`, доступные
внутри образа. `model_unit` должен соответствовать обозначению котла в экспорте.
Полные рабочие датасеты и обученные модели с рабочего ПК в этой области не представлены.

## Docker

Из этой папки:

```console
docker compose build dashboard
docker compose up -d --no-build --force-recreate dashboard
```

Сборка создаёт frontend, устанавливает зависимости backend и копирует данные
и модели в образ. Volumes в текущем Compose не используются.
`backend/.env` подключается через `env_file` в Compose.
`.dockerignore` исключает локальные node_modules, кэши и старые архивы из контекста сборки.

## Сохранённые ускорения

- На странице котла изменение даты запрашивает только его расчёт; сводка
  загружается при открытии «Все станции» на текущую дату.
- Токен передаётся существующим authFetch, включая запросы с сигналом отмены.
- Устаревшие ответы сводки не подменяют актуальные.
- Подготовка входов не повторяется ради получения маски пропусков.
- Известный алгоритм причинной очистки векторизован и обрабатывает данные блоками.
- AAKR, MSET и аналоги повторно используют результаты только для полностью
  совпавших подготовленных векторов одной загруженной модели.
- `/api/health` без параметров не запускает модели; `?deep=true` включает полную проверку.

Кэш прогнозов по умолчанию ограничен 128 МиБ на процесс; лимит задаёт
`MODEL_ROW_CACHE_MB`. `MODEL_ACCELERATION=0` отключает ускорение подготовки
и прогноза для сравнения. Первый расчёт новой модели или далёкой даты может
потребовать полного вычисления. Одновременные расчёты одного котла по-прежнему
защищены блокировкой; несколько серверных процессов отдельно не настраивались.

## Проверки

Из корня рабочей области в существующем окружении Python:

```console
python -m unittest discover -s dashboard/tests -v
```

Тесты авторизации используют тестовый провайдер и не обращаются к корпоративному Keycloak.
