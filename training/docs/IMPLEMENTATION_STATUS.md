# Выполненные изменения и границы проверки

Основной вход: `02_Обучение.ipynb`, настройки `incremental_settings.json`.
Инструкция запуска: [INCREMENTAL.md](INCREMENTAL.md).

Конфиденциальные данные для разработки не требуются. Они не были предоставлены.
Реальные пороги, назначения каналов, причины остановов и эксплуатационное качество
нужно проверять локально, без передачи телеметрии.

| Пункт плана | Что реализовано | Что требует локальной проверки |
|---|---|---|
| 1. Исходная история | Аудит каналов, единиц, дублей, разрывов, порога, состояний, графики | Доступность и корректность реальных источников |
| 2. Режимы | Каузальное определение, неизвестная нагрузка, сохранённый порог, явные длительности | Физический порог и длительность пуска каждого котла |
| 3. События | Реестр отметки/останова/окончания, источник, незавершённость и достоверность | Причины и подтверждение отдельных событий |
| 4. Очистка | Правила по каналам; редкие состояния и переходы сохраняются; качество отдельно | Типы каналов, пределы, допустимость маскирования |
| 5. Входы и цели | Исходные категории, пропуски целей исключены, фиксированная схема, опорные постоянные цели | Разрешение и масштаб конкретных датчиков |
| 6. Обновление | Наследование CatBoost; память и достаточные статистики analogs/AAKR/MSET; checkpoints | Скорость обновления и пригодность лимитов для реального объёма |
| 7. Деградация | Закреплённая норма, задержка допуска, replay, отбор кандидата, журнал наследования | Баланс адаптации и чувствительности к деградации |
| 8. Оценки отклонения | max/top5/mean/fraction/группы, текущая и медленная оценки, покрытие | Группы и предпочтительная схема |
| 9. Тревоги и метрики | Подтверждение без сдвига назад, фоновая длительность, бюджеты, общие часы, интервалы | Допустимая нагрузка тревог и полезность предупреждений |
| 10. Варианты CatBoost | Условия, прогноз, связанные датчики, поправка к analogs, общие деревья целей | Физические связи и сравнительное качество |
| 11. Интерпретация | Каталог, метки с датой доступности, две задачи, временная проверка, калибровка, воздержание | Размеченные эпизоды и достаточное число независимых аварий |
| 12. Применение | Экспорт с собственным runtime и манифестом, месячные версии, ноутбук 03, адаптер/API/интерфейс | Проверка в целевом окружении и эксплуатационный приём |

Основной код нового конвейера находится в `lib/monitoring_v3/`. Прежний `legacy_*`
сохранён как историческая база; его fast/refit не являются режимами нового конвейера.
HistGradientBoosting в новом сравнении явно заморожен — его обновление не выдаётся за дообучение.

## Проверки

Проверены 40 тестов: 39 успешно, один пропущен из-за отсутствующего архивного эталона.
В их числе проверка исследования Cox с независимыми циклами.

Проверены наследование прежних деревьев CatBoost, неизменность прогнозов при добавлении
будущих данных, отсутствие зависимости прогноза от отметок ремонта, первые изменения
постоянных целей, постоянные условия, пропуски, обновление памяти без первоначального
fit, перенос между котлами, загрузка экспорта в свежем процессе, восстановление
месячной цепочки и исторический выбор модели в сервисе дашборда.

Сборка интерфейса `npm run build` пройдена. `pip check`, компиляция Python и
`git diff --check` пройдены. Проверены успешный предварительный запуск ноутбука
на искусственных источниках и ненулевой код завершения при отсутствующих источниках.

## Демонстрационный прогон

`runs/validated_incremental/` содержит исключительно искусственные данные, помеченные
`SYNTHETIC_ONLY.txt`. Семь моделей, восемь конфигураций, три месячных среза:

* 240 строк сравнения схем и бюджетов тревог;
* 240 строк сравнения на общих часах;
* 24 месячных экспорта;
* 150 строк проверки чувствительности;
* диагностика пересечения квантилей и покрытия центрального интервала;
* состояния «недостаточно данных» для месяцев без подходящих проверочных участков.

На этой истории две искусственные аварии. Обучение предаварийной интерпретации и
survival обоснованно возвращает недостаток независимых событий, а определение причины
требует проверенных меток. Отдельными тестами проверены и положительные пути обучения
классификатора/продолжения обучения и Cox при достаточном количестве генерируемых групп.

Результаты не определяют лучшую модель для реальных котлов. Порог бюджета на калибровке
не гарантирует ту же частоту тревог на последующей истории — обе величины сохраняются.

## Единый ноутбук подготовки и разбора

`02_Обучение.ipynb` выполняет аудит, обучение, сравнение, разметку эпизодов и
интерпретацию без запуска отдельных скриптов. Дополнительные исследования доступны
в последнем блоке. Служебные функции используются совместно с CLI, чтобы расчёты
не расходились между двумя способами запуска.

На искусственной истории выполнены все 10 расчётных ячеек без ошибок; в сохранённой
копии `runs/validated_incremental/02_all_in_one.ipynb` находятся 45 HTML-таблиц и
два встроенных графика. Дополнительно проверен запуск трёх исследований из функций
ноутбука: объединённые признаки, корректный статус недостатка событий для survival
и 150 строк проверки чувствительности.

Четыре проверки нового интерфейса подтверждают сохранение исходных правил,
пакетную проверку разметки перед записью, использование уже загруженных данных
при интерпретации и обработку пустого CSV-отчёта в Windows.

## Начать локальную проверку

1. Открыть `02_Обучение.ipynb` и указать доступные только локально пути в `SETTINGS`.
2. Заполнить назначения в `SENSOR_RULES`; спорное маскирование по умолчанию отключено.
3. Выполнить Run All: режимы, реестр событий, сравнение и графики появятся в ноутбуке.
4. Для проверенных причин заполнить `EPISODE_LABEL_EDITS` и выполнить ячейки меток
   и интерпретации. Результат «не определено» сохраняется при недостатке оснований.
5. Дополнительные исследования включаются в `RESEARCH`; отдельные команды не нужны.

Изменённый код, настройки или данные прошлого требуют новой папки результатов. Готовые
таблицы/графики читаются без обучения; старую цепочку нельзя молча продолжать новым кодом.
