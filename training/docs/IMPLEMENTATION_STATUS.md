## Проверки

Переключатель `validate_candidate` проверен отдельно девятью целевыми тестами;

После аудита зависания калибровки исключён deepcopy нативных CatBoost из кандидата

прошёл до/после изменения; калибровка теперь различает обновляемую и исходную модель.
В их числе проверка исследования Cox с независимыми циклами.

Проверены наследование прежних деревьев CatBoost, неизменность прогнозов при добавлении
будущих данных, отсутствие зависимости прогноза от отметок ремонта, первые изменения
постоянных целей, постоянные условия, пропуски, обновление памяти без первоначального
fit, перенос между котлами, загрузка экспорта в свежем процессе, восстановление
месячной цепочки и исторический выбор модели в сервисе дашборда.

Сборка интерфейса `npm run build` пройдена. `pip check`, компиляция Python и

на искусственных источниках и ненулевой код завершения при отсутствующих источниках.

## Демонстрационный прогон

`runs/validated_incremental/` содержит исключительно искусственные данные, помеченные
`SYNTHETIC_ONLY.txt`. Семь моделей, восемь конфигураций, три месячных среза:

* 240 строк сравнения схем и бюджетов тревог;
* 240 строк сравнения на общих часах;
* 24 месячных экспорта;
* 150 строк проверки чувствительности;
* диагностика пересечения квантилей и покрытия центрального интервала;
* состояния «недостаточно данных» для месяцев без подходящих проверочных участков.

На этой истории две искусственные аварии. Обучение предаварийной интерпретации и
survival обоснованно возвращает недостаток независимых событий, а определение причины
требует проверенных меток. Отдельными тестами проверены и положительные пути обучения
классификатора/продолжения обучения и Cox при достаточном количестве генерируемых групп.

Результаты не определяют лучшую модель для реальных котлов. Порог бюджета на калибровке
не гарантирует ту же частоту тревог на последующей истории — обе величины сохраняются.

## Единый ноутбук подготовки и разбора

`02_Обучение.ipynb` выполняет аудит, обучение, сравнение, разметку эпизодов и
интерпретацию без запуска отдельных скриптов. Дополнительные исследования доступны
в последнем блоке. Служебные функции используются совместно с CLI, чтобы расчёты
не расходились между двумя способами запуска.

На искусственной истории выполнены все 10 расчётных ячеек без ошибок; в сохранённой
копии `runs/validated_incremental/02_all_in_one.ipynb` находятся 45 HTML-таблиц и
два встроенных графика. Дополнительно проверен запуск трёх исследований из функций
ноутбука: объединённые признаки, корректный статус недостатка событий для survival
и 150 строк проверки чувствительности.

Четыре проверки нового интерфейса подтверждают сохранение исходных правил,
пакетную проверку разметки перед записью, использование уже загруженных данных
при интерпретации и обработку пустого CSV-отчёта в Windows.

## Начать локальную проверку

1. Открыть `02_Обучение.ipynb` и указать доступные только локально пути в `SETTINGS`.
2. Заполнить назначения в `SENSOR_RULES`; спорное маскирование по умолчанию отключено.
3. Выполнить Run All: режимы, реестр событий, сравнение и графики появятся в ноутбуке.
4. Для проверенных причин заполнить `EPISODE_LABEL_EDITS` и выполнить ячейки меток
   и интерпретации. Результат «не определено» сохраняется при недостатке оснований.
5. Дополнительные исследования включаются в `RESEARCH`; отдельные команды не нужны.

Прежняя output сохраняется при обновлениях. Совместимые состояния проверяются
и восстанавливаются; изменённые данные/параметры вызывают пересчёт нужных частей
с резервной копией прежнего checkpoint. Непроверяемая старая версия не принимается молча.

## Устранение длительных пауз и сохранение готовых моделей

Устранена фрагментация pandas при сопоставлении большого числа каналов, создании
условий, прогнозных входов и признаков интерпретации. Топ-5 и поиск границ тревог
векторизованы. Калибровка порогов использует ту же последовательность кандидатов
и правила уведомлений без создания тысяч промежуточных DataFrame.

Оценка месячного среза ограничена месяцем и необходимой предысторией для лагов и
скользящих окон. Отдельно проверено совпадение с оценкой полной истории для условий
и прогнозов на 1/6 часов. Готовые месячные оценки кэшируются с учётом версии модели
и входных данных; изменение незавершённого месяца делает соответствующий кэш непригодным.

Готовый экспорт публикуется до расчёта оценок месяца. `models.csv` содержит актуальные
пути для дашборда, `progress.jsonl` — этапы и время. При ошибке последующего расчёта
готовый экспорт остаётся; при неудачной замене папки восстанавливается прежняя версия.
Проверены восстановление после прерывания без начального fit, использование кэша,
загрузка модели сервисом дашборда и импорт экспорта в отдельном процессе.

В эту проверку входят 27 новых регрессионных тестов в `checks/` и 43 проверки из
локального набора `tests/` (одна пропущена). Скорость на реальной конфиденциальной
телеметрии не измерялась. Старые checkpoints продолжаются только после проверки
совместимости; вручную менять output при обновлении не требуется.

Полный сравнительный прогон текущего конвейера до/после оптимизации на одинаковой
искусственной истории: 158.0 → 59.5 с, восемь конфигураций, 240 строк сравнения.
Ошибки датчиков, моменты уведомлений и эпизоды тревог совпали. У скользящих оценок
есть различия округления до примерно 9.1e-13; на плато это изменило ранговую AP
максимум на 0.00362. Равенство всех ранговых метрик побитно не заявляется.
Подробности: [PERFORMANCE.md](PERFORMANCE.md).

Для обычного CatBoost теперь видны отдельные цели, итерации, число входов,
кардинальность категорий и фактический лимит потоков. Завершённые цели первого
обучения пишутся в `partial/`; незавершённая цель при повторе обучается заново.
Пять тестов проверяют восстановление, совместимость, преобразование входов,
оптимизацию проверки изменчивости и перенос завершённых целей из traceback
старого прерванного запуска в новую output. Дообучение восстанавливается с
месячного checkpoint. Частичные цели сами по себе не являются экспортом для дашборда.

Отдельный искусственный пример с 5 556 строками, 226 целями, 20 входами,
150 деревьями глубины 4 и двумя потоками обучился за 145.8 с. Реальную причину
многочасового расчёта на конфиденциальной телеметрии этот пример не устанавливает.
Перенос из старого ядра требует выполнить `rescue_initial` до перезапуска;
порядок и ограничения — в разделе 21.4 основной инструкции.

Месячная проверка обычного CatBoost переиспользует один временный Pool для
всех целей старой и новой модели. Отдельные таймеры и прогресс прогнозов
различают копирование, дообучение, память, подготовку входов, старую/новую
модель и решение. Шесть проверок подтверждают точное совпадение прогнозов,
неизменность принятия кандидата, сериализацию, однократную упаковку,
порядок сообщений и локализацию исключений. Полное время каждого датчика
записывается в progress.jsonl; в ноутбуке используется один обновляемый
прогресс-бар с текущим подэтапом, датчиком, итерациями и временем.
Профиль с 226 целями подтверждает один проверочный Pool вместо 452;
причина задержки на конфиденциальной телеметрии пока не установлена.
Порядок установки: [PREDICTION_UPDATE.md](PREDICTION_UPDATE.md).

Четыре дополнительные проверки подтверждают один блок вывода без потери журнала,
ограничение частоты обновления, безопасное отображение имён, текстовый резерв
при сбое интерфейса и полноценное выполнение двух месяцев в настоящем Jupyter-ядре.
Дополнительные виджеты не нужны; обычный Python продолжает выводить текстовый журнал.

## Доработка качества, 26–27 октября 2026

Кодовые этапы [плана](ПЛАН_ДОРАБОТКИ_КАЧЕСТВА.md) выполнены. Актуальные решения,
все новые настройки, примеры, ограничения и порядок переноса описаны в
[КАЧЕСТВО_И_ПЕРЕНОС.md](КАЧЕСТВО_И_ПЕРЕНОС.md). Предыдущие разделы этого документа
содержат результаты более ранних этапов, а не замер качества нового конвейера
на реальной телеметрии.

- Общий загрузчик времени, дублей и числовых состояний применяется в обучении,
  сохранённой модели и backend. Отсутствующие объявленные каналы сохраняют NaN.
- Все токи — условия; введены группы приводов, однозначные пары мельница/питатель,
  ручные уточнения, мазутные свидетельства, покрытия и конфликты. Выходной ток
  управления не подменяет ток двигателя. Пороги фиксируются по раннему прошлому.
- Физические остановы подтверждаются наблюдаемой нагрузкой; один низкий отсчёт,
  удержанный во время пропуска, не создаёт второй отсчёт подтверждения. Неизвестные
  причины и документы без найденного останова сохраняются в реестре.
- Разбиение использует всю прошлую зрелую норму и постоянный независимый резерв.
  Первый fit не требует отдельной проверки кандидата; выключенная проверка
  не резервирует строки. Пустая последняя неделя не мешает старым кампаниям.
- Включён причинный исторический bootstrap до даты основного отчёта. Граница
  опорного периода ровно первого числа не пропускает лишний месяц.
- Калибровка показывает объём, ограниченность, возраст и неопределённость частоты.
  Поцелевые физические ошибки сравниваются с константой; проверка кандидата
  учитывает провалы отдельных и критических целей. Редкие изменения — отдельные
  события, без многомесячной непрерывной тревоги от одного нового уровня.
- Добавлены сравнение полностью замороженной первой модели и адаптации на
  1/3/6 месяцах и всей проверке, наблюдаемые/ненаблюдаемые события и неизвестный фон.
- Риск собирает независимые эпизоды по группе котлов. Полное будущее обязательно
  для отрицательной метки; уже наблюдённая авария не ждёт окончания остатка H.
  Рабочая модель, групповой резерв вероятностей и независимые временные проверки
  разделены. Окна защищены от пересечений, минимум обучающих событий сохранён.
  Новые спокойные эпизоды после последней аварии продолжают рабочую голову.
- Недостаток калибровки даёт trained_uncalibrated, а не ложные проценты или запрет
  любой модели. Лимит деревьев сохраняет веса и настоящую дату обучения; новые
  необученные строки не записываются как уже использованные. Причины требуют
  проверенных меток. Исправленная старая метка/новый класс создаёт новую версию.
- Экспорты используют ту же подготовку/окна, правильные даты доступности и variant.
  Неуспешная новая голова не оставляет активную старую молча. Дашборд не называет
  отклонение диагнозом, а неоткалиброванный балл — вероятностью.
- Добавлена feature importance PredictionValuesChange по целям и головам,
  сводка по реально обученным целям, изменения версий, кэш и графики ноутбука.
  Месяц/цель выбираются в DETAIL. Это глобальная опора модели, не причина тревоги.

Проверки: полный набор **82 теста прошёл** за 187.6 с. После последнего уточнения
цензурирования и просмотра выполнены **45 проверок** (78.4 с) и отдельная проверка
выбора месяца importance/совпадения runtime. Настоящее Jupyter-ядро выполнило все
12 кодовых ячеек контрольного экземпляра основного ноутбука на искусственной
истории: bootstrap раньше first_test, экспорт, отчёты, интерпретация и график
важности. Сборка frontend `npm run build`, компиляция Python и проверка diff прошли.
Полезные локальные свидетельства: `runs/quality_all_final.log`,
`runs/quality_update/final_checks.log`, `runs/quality_update/notebook_validation.json`.

Код изменил смысл подготовки и отложенных выборок: **STATE_CONTRACT=3** требует
одного пересчёта прежней цепочки с сохранением старых checkpoints. После этого
совместимые новые месяцы дообучают модель, повтор старого расчёта не делает fit.

Частота ложных тревог, recall, качество вероятностей, пороги токов и реальный
выигрыш вариантов на закрытой телеметрии не измерены. Неизвестные причины
остановов автоматически не превращены в подтверждённые аварии или норму.

## Общий цикл в разделе 3, LiveReport, pandas и Precision

Уточнённый запрос реализован в соответствии с

  после регрессоров котлов обновляется риск, затем те же графики раздела 3.
- Головы реально продолжают прежние деревья новыми зрелыми примерами и replay.
