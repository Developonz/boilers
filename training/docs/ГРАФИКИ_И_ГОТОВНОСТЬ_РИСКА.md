# Живые графики и готовность классификаторов риска

## Что нужно для работы классификаторов

Большое число часов само по себе не заменяет аварии. По стандартным настройкам
рабочей голове риска нужны минимум **две независимые аварийные группы и две
фоновые группы в обучении**. Для калибровки процентов нужны **ещё минимум две
группы каждого класса**, не использованные в fit. Это нижняя граница допуска,
а не обещание достоверной вероятности на четырёх авариях.

Условия проверяются отдельно для 24 и 168 часов:

1. Есть сохранённые исторические признаки регрессора. Для часов до первой
   готовой модели их нет. `history_policy.bootstrap=True` получает признаки
   на ранней доступной истории, не ограничивая их только `first_test`.
2. Рабочее окно пригодно: достоверная работа, достаточно оценок датчиков,
   не меньше половины 24-часового окна. Пропуски и неизвестный режим не
   объявляются нормой. Ограничения нельзя обходить подстановкой нулей.
3. В `samples="episodes"` есть активная подтверждённая тревога **mean::instant**.
   Точки обучения берутся при подтверждении и далее каждые `sample_hours=6`.
   Авария без таких точек не создаёт положительный пример автоматически.
4. У положительной точки впереди наблюдается останов, который известен как
   аварийный, внутри горизонта и с упреждением минимум 3 часа. Метка доступна
   после останова, его подтверждения и появления аварийной отметки.
5. Отрицательный пример требует наблюдаемого будущего на весь горизонт без
   конкурирующего останова. Плановый/неизвестный останов, провал нагрузки и
   короткий хвост данных исключают пример; это не отрицательный класс.
6. Группы разделены с учётом окон. Для 24 часов защитный промежуток 72 часа,
   для 168 часов — 216 часов. Близкие эпизоды могут не дать независимый резерв.

При `risk_policy.scope="group"` данные котлов одного семейства объединяются.
В таблице готовности указаны область и состав группы: одинаковые групповые
числа рядом с К-5 и К-6 нельзя складывать как независимые оценки.

### Что делать в зависимости от результата

| Что видно | Что означает и какое действие имеет смысл |
|---|---|
| Зарегистрировано аварий 5, положительных групп 0 | Проверить, были ли перед ними признаки, пригодные окна и тревоги mean::instant. Новая таблица показывает аварии без примеров, их ID есть в label_audit |
| В регистре аварий меньше, чем известно специалисту | Проверить сопоставление ремонтов с остановами по нагрузке и подтверждённые `event_overrides`; неизвестным остановам не присваивать «авария» наугад |
| Не хватает положительных групп в обучении | Использовать более раннюю доступную историю, корректную группу котлов; проверить пропущенные события и условия отбора. Уменьшение min_positive_events до 1 не подтверждает переносимость |
| Много аварий без тревог | Разобрать качество регрессора/порога. Для сравнения можно отдельно запустить `risk_policy.samples="continuous"`: это риск на регулярных рабочих точках, другая постановка |
| Много исключений по неполному будущему | Последним 168 часам нельзя дать отрицательную недельную метку. Для них нужен следующий фрагмент наблюдений, а не заполнение нулями |
| `trained_uncalibrated` | Обученный балл уже доступен. Для процентов нужен независимый резерв событий после защитных исключений |
| Итоговая модель обучена, но на раннем графике нет риска | Тогда ещё не были известны необходимые аварии. Новая модель не получает права задним числом предсказывать собственную историю |

Причины отклонений — отдельный классификатор. Ему нужны проверенные смысловые
метки хотя бы нескольких классов; аварийный исход автоматически не объясняет
поломку конкретного узла.

## Что теперь выводится при обучении

В разделе 3 для каждого сочетания метода, варианта, сценария и котла создаются:

1. Собственный обновляемый блок. «Месячные срезы» показывают, сколько из
   запланированных месяцев обработано, включая пропущенные по недостатку данных.
   Ниже отдельно показывается прогресс датчиков текущей операции. Это не ETA
   всего запуска и не утверждение, что все обработанные месяцы обучились.
2. График прежнего вида: сверху суточный максимум ошибки/порога, линия 1,
   цвета аварийного/планового ремонта, резерва и простоя. Снизу две полосы:
   работа котла и подтверждённая тревога. Масштаб выше 1 сжат как в legacy.
3. Обновляемая раскрываемая таблица готовности и всех тревог с риском.

График меняется после каждого рассчитанного месяца. Предыдущие блоки не
заменяются следующим котлом. Для pooled один общий ансамбль отражается
на карточках всех получателей; это не независимое обучение по каждому котлу.

Отличия, необходимые для достоверности: ноль рисуется только при достоверном
простое, неизвестный режим имеет свою штриховку, работа без оценки — свою.
Суточный максимум способен скрыть внутрисуточный провал; точная часовая
доступность остаётся в parquet и подробном диагностическом графике.

## Откуда берутся исторические подписи риска

Риск добавляется после раздела 7. При pooled сначала нужны признаки всех котлов
группы. До этого графики детекторов уже видны, но риск обозначен как нерассчитанный.

Для честной истории отдельно воспроизводится обучение голов на начало каждого
месяца:

```text
1 мая: fit только по примерам и меткам, известным на 1 мая → оценки мая.
1 июня: продолжение по информации, известной на 1 июня → оценки июня.
```

Сохраняются постоянные калибровочные группы, групповой replay и защитные интервалы.
Классификаторы этой истории независимы от итоговых рабочих голов. Внутренние
дополнительные временные проверки каждого fit выключены, чтобы не повторять
их десятки раз; сама следующая месячная история является применением вне fit.
Неполное будущее мешает размечать пример, но не запрещает сделать прогноз по
пригодным текущим входам. Поэтому последние часы тоже могут получить риск.

Это дополнительный расчёт небольших классификаторов, а не ещё один прогон
226 регрессоров. При первом выполнении он занимает время. Завершённая история
кешируется по признакам, событиям, наблюдаемости и настройкам; она не пересчитывается
при повторном запуске с теми же входами. Начатый, но незавершённый такой расчёт
пока не возобновляется с отдельного исторического месяца. Регрессионные
checkpoints и итоговые головы от этого не теряются.

Примеры подписей:

```text
#1 24ч 34%→46% / 168ч балл 0.55→0.67
#2 24ч нет оценки / 168ч нет оценки
```

Первое число — оценка **в момент подтверждения тревоги**. После стрелки —
максимум **по мере её последующего развития**. Он не был известен в начале.
«Балл» — некалиброванный выход модели, его нельзя читать как 55% вероятности.
Если голова появилась позже начала эпизода, подпись содержит «позже»; таблица
показывает точную дату первой доступной оценки. Если сначала был только балл,
а потом стала доступна вероятность, это также разделено.

Номер связывает подпись с полной таблицей всех тревог. При длинной истории
подписи могут быть плотными: задайте `LIVE.start/end` или `DETAIL.start/end`.
Результаты не теряются из-за сокращения текста графика. Для схем, отличных
от mean::instant, в режиме episodes риск доступен только там, где также
активна основная тревога: условия применения классификатора не подменяются.

## Все новые параметры отображения

`LIVE` находится в ячейке настроек отдельно от `SETTINGS`. Это не параметры
обучения основного детектора и они не меняют его контракт.

| Поле | По умолчанию | Значение |
|---|---|---|
| `enabled` | `True` | Создавать отдельные блоки и живые графики; False оставляет обычный общий индикатор |
| `update_every_months` | `1` | Обновлять рисунок каждые N месячных срезов; целое >=1; последний рисуется всегда |
| `risk_history` | `True` | В разделе 7 строить отдельную причинную историю риска; False экономит этот расчёт, итоговые головы всё равно обучаются |
| `view` | `"mean::instant"` | Схема тревог на живом графике; должна быть рассчитана |
| `budget` | `None` | None — основной alarm_budget; иначе один из рассчитанных alarm_budgets |
| `start` | `None` | Начало картинки; None — first_test. Не меняет обучение или отбор меток |
| `end` | `None` | Конец картинки; None — весь рассчитанный период. Не меняет обучение |

`DETAIL.style="legacy"` по умолчанию показывает те же две панели.
`DETAIL.style="diagnostic"` оставляет подробные три панели: часовой показатель,
покрытие и остатки датчиков. DETAIL не меняет живые карточки.

Если графики слишком замедляют обучение, задайте `update_every_months=3`.
Если сейчас нужны только регрессоры и итоговая голова, задайте
`risk_history=False`: исторические проценты при этом не выдумываются.

## Файлы и повторный запуск

В папке каждого получателя эксперимента:

- `training_plot.png` — последний рисунок живой карточки;
- `alarm_risk.csv` — все тревоги, оценки при подтверждении, последующие максимумы,
  даты доступности и причины отсутствия;
- `classifier_readiness.csv` — независимые группы, дефициты и исключённые примеры;
- `risk_timeline.parquet` — почасовая история риска с `model_cutoff`, горизонтом,
  `probability`, `raw_score`, статусами;
- `risk_timeline.meta.json` — происхождение истории и хеш исходных признаков.

В корне output — общая `classifier_readiness.csv`; в `risk_history/` —
независимые исторические головы, кеш и подробные `months.json`.
История от иных признаков не подставляется в подробный график молча.

Для использования: обновить файлы, перезапустить ядро, выполнить настройки,
подготовку, раздел 3 и затем раздел 7 (либо Run All). Готовые совместимые
регрессионные checkpoints восстанавливаются; это изменение отображения
само по себе не требует перехода на новый контракт или полного переобучения.
После перезапуска ядра старые карточки нельзя обновить по утраченным display_id:
повторный раздел 3 создаёт новые, раздел 7 затем дополняет их.

Без исходной конфиденциальной телеметрии проверяется причинность и работа
кода. Достаточность реальных аварий и качество вероятностей определяются
локальными таблицами готовности и последующей проверкой.
