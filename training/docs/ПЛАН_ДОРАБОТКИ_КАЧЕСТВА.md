# Доработка качества: решения, риски и критерии готовности

Дата начала: 26 октября 2026. Основание — аудит текущего кода и сохранённого прогона. Рабочий код и предыдущие результаты сохраняются. Реальная телеметрия остаётся у владельца; инженерные пороги и фактическое качество на ней не выдумываются.

## 1. Договоры, которые должны выполняться

1. Достаточная старая история не блокируется пустой последней календарной неделей. Каждый непроведённый запуск объясняется реальным числом пригодных строк и статусом порога.
2. Часы, зарезервированные для калибровки, не попадают в обучение этой или последующих версий. Будущее не участвует в подготовке исторического решения.
3. Отсутствие новой нормы сохраняет предыдущий готовый детектор. Обновление модели без пригодного основного порога не подменяет рабочую версию.
4. Неизвестный останов не становится отрицательной меткой риска. Пропуск нагрузки не считается физическим остановом. Один физический останов имеет одну запись.
5. Токи описывают состав оборудования, нагрузка — выпуск пара. Мельница без питателя не доказывает горение; отсутствие тока не запрещает мазутный режим.
6. Признаки, очистка и окна одинаковы при обучении, проверке и применении. Неполные окна имеют явное покрытие, непригодные результаты — явную неизвестность.
7. Состояния «можно обучить», «вероятность откалибрована», «есть аварии для оценки» разделены. Модель без подтверждённых вероятностей не выдаёт уверенные проценты.
8. Обновление схемы подготовки инвалидирует несовместимое состояние, сохраняя предыдущие файлы. Изменение журнала не должно терять обучение.

## 2. Последовательность работ

| Этап | Изменение | Предусмотренные проблемы | Критерий |
|---|---|---|---|
| Подготовка | Единая сетка и обработка дублей, физические роли, политика входных каналов | Числовые состояния нельзя усреднять; отсутствие обязательного входа не скрывать | Одинаковый файл даёт одинаковые входы в обучении и backend |
| Режим | Сохранённые пороги токов по ранней прошлой истории; группы мельниц/питателей/тяги; конфликты и неизвестность | Холостой ход, продувка, мазут, пропуски, разные приводы, слабое разделение токов | Известная паровая нагрузка не отменяется отсутствием токов; потеря нагрузки не превращается в останов |
| Реестр | Все подтверждённые нагрузкой остановы плюс документы, дедупликация, конфликты и неизвестные причины | Один останов/несколько заявок, нет документа, документ без найденного останова | Неизвестное не обучает класс «нет аварии» |
| Разбиение | Постоянные календарные блоки holdout по всей прошлой пригодной истории; проверка только при включении | Калибровка не переезжает в train при следующем месяце; разрывы не склеиваются | Годовая история с пустым последним месяцем позволяет стартовать при наличии отложенных часов |
| Исторические признаки | Более ранние последовательные модели до first_test для классификатора | Пороги подготовки не используют позднее будущее; стоимость отражена в плане | Ранняя история не исчезает только из-за даты основного отчёта |
| Калибровка | Более длинная резервная история, покрытие режимов, статус/возраст/неопределённость порога | Короткий участок не различает месячные бюджеты; нестабильный разброс редких целей | Нет принятой версии с непригодным основным порогом; все ограничения видны |
| Модели | Явная балансировка по нагрузке; независимая проверка критических каналов; измеренный внеобучающий пол масштаба | Медиана скрывает один плохой узел; деревья достигают лимита | Причина принятия/отказа по целям и группам сохраняется |
| Тревоги | Согласованные окна/покрытие, сводка вклада, отделение событий редких каналов | Постоянная тревога с одним сообщением; скрытое разбавление критической цели | Длительность и сообщения оцениваются отдельно; типы результатов не смешиваются |
| Риск | Групповой набор котлов, эпизоды как единицы решения, проверка будущего окна, временные проверки | 3 события нельзя делить 3+1+1; пустой положительный тест; повторные точки одной аварии | Нет общего неинформативного запрета; сохраняются составы классов и независимых событий |
| Смысл | Проверенные причины, неизвестность и описательные подсказки | Автоматические риск-метки не равны причинам | Не создаются вымышленные метки диагнозов |
| Эксплуатация | Полная предыстория либо явный её статус, правильные даты/variant, пригодность риска, версии голов | Старый классификатор не должен незаметно подключаться после отказа нового; ограниченная история меняет ages | Совпадение одного часа в сохранённом runtime и обучении |
| Отчёты | Доступность, наблюдаемые/ненаблюдаемые аварии, длинный период, замороженная и обновляемая версии | Качество нельзя повышать удалением неудобных аварий; итоговую модель нельзя применять в обучающем прошлом | Доступность и качество работающей модели показаны одновременно |
| Важность входов | Нативная важность отдельно по целям и головам, сравнение версий, таблицы и диаграммы | Коррелированные входы делят влияние; сводка не равна критичности; итоговая версия не объясняет старую тревогу | Версия подписана, неподдерживаемые/константные цели не разбавляют среднее, веса не меняются |

## 3. Проверка без закрытой телеметрии

Осмысленные сценарии: год старой нормы и месячный простой; отключённая проверка кандидата; разнесённые рабочие кампании; один котёл pooled без часов; один постоянный датчик с важным изменением; пропуск нагрузки и работающие мельницы; мазут при выключенных мельницах; неизвестный останов; конфликт ремонта/резерва; отсутствие аварий в тесте; три аварии; неполное будущее; граница месяца; позднее появление метки; повторный запуск и смена версии; перенос экспорта и равенство расчёта выбранного часа.

Проверяются контракты данных и алгоритма, а не искусственно красивый recall. Скорость и качество на реальных котлах потребуют локального прогона. Долгие несвязанные проверки не повторяются без новых изменений или причин.

## 4. Результаты, которые нужно передать

- Исправленные модули и ноутбуки с понятными настройками.
- Обновлённая инструкция и описание изменившегося поведения.
- Точный отчёт о проверках и оставшихся ограничениях.
- Переносимый комплект для другого ПК, без телеметрии и пользовательских секретов.
- Список миграционных изменений: какие старые модели больше нельзя продолжать из-за нового смысла признаков/калибровки.
