# Обновление проверки CatBoost и прогресс-бар в ноутбуке

## Как установить

1. Если обучение ещё идёт, прервите ячейку и дождитесь завершения прерывания.
2. Распакуйте `training_update_validation.zip` в корень вашей копии `boilers-main`
   с заменой файлов. Архив содержит код, проверки и инструкции. Ноутбук,
   SETTINGS, JSON-настройки, телеметрия и прежние результаты в него не входят.
3. Перезапустите ядро Python: замены файлов недостаточно для уже импортированных классов.
4. Укажите новую `"output": "runs/incremental_validation"` и выполните ноутбук сверху вниз.
   Код входит в проверку совместимости: старая цепочка checkpoints этим обновлением
   автоматически не продолжается. В новой папке первоначальное обучение выполняется
   заново один раз; следующие месяцы продолжают предыдущую модель. Прежние готовые
   экспорты остаются доступны в старой папке.

Отдельно запускать скрипты не нужно. Обновляемый индикатор автоматически появится
в ячейке обучения Jupyter/VS Code. Дополнительные пакеты виджетов не требуются.

## Как попробовать без проверки кандидата

Добавьте в `SETTINGS`:

```python
"validate_candidate": False,
```

По умолчанию `True`. При `False` обновлённая модель принимается после успешного
дообучения без подготовки проверочного набора, прогнозов старой/новой версии и
сравнения ошибок. В журнале появится «Обновление принято без проверки кандидата»;
в аудите — `validation_status="disabled"`. Копирование предыдущей модели, отбор
пригодных часов, старые примеры, разделение истории и калибровка порогов сохраняются.
То есть ухудшившееся обновление тоже может быть принято. Проверка кандидата не
является требованием CatBoost; она добавлена в новом конвейере. В legacy-версии
такого сравнения месячного кандидата не было.

Старые примеры — до 500 строк из памяти до 1500 строк, выбранные для покрытия
состояний механизмов и диапазонов первого числового входа (обычно нагрузки).
Это не подбор ближайших к новому месяцу часов. Исходные измерения не изменяются.

## Что исправлено

Обычный CatBoost теперь готовит один `Pool` на проверочную таблицу и использует его
для всех датчиков старой и обновлённой модели. Раньше одна и та же таблица повторно
упаковывалась при каждом `predict` — до 452 раз для 226 датчиков.

В остальных прогнозах и диагностике интервалов обычного CatBoost упаковка также
выполняется один раз на таблицу. Для HistGradientBoosting числовые входы готовятся
один раз для всех датчиков и трёх квантилей. Для Related/Correction/Multi сохраняются
их собственные схемы входов. `Pool` существует только во время прогноза, в состояние
модели и экспорт не записывается.

## Что будет видно после обучения цели 226/226

Подэтапы имеют отдельное имя и собственное время в индикаторе:

1. Копирование предыдущей модели.
2. Дообучение кандидата: подготовка новых и старых строк, обучение целей.
3. Обновление памяти примеров.
4. Подготовка общих проверочных входов.
5. Проверочные прогнозы старой модели.
6. Проверочные прогнозы новой модели.
7. Сравнение ошибок и решение об обновлении: «Кандидат принят» либо «Кандидат отклонён».

Пример содержимого одного обновляемого блока (время условное):

```text
Этап: ... · проверочные прогнозы старой модели: 268 строк
[████████░░░░░░░░░░░░] Датчики: 85/226 · 37.6%
Текущий датчик 86/226: уровень в барабане · 2.3 с
Этап: 15.0 с · всего: 18 мин 04 с
```

Быстрые сообщения обучения и прогнозов обновляют этот же блок, вместо добавления
строк. Видны завершённые датчики, имя текущего, время подэтапа и всего запуска;
при обучении — также итерации CatBoost. Процент относится к датчикам текущего
прохода, а не ко всему многомесячному расчёту. У копирования, памяти и подготовки
входов неизвестен объём работы: индикатор показывается без выдуманного процента.

Обновления быстрых событий ограничены примерно 2–3 в секунду. Переключения этапов,
их завершение и ошибки отображаются сразу. На долгих этапах время обновляется
примерно каждые полсекунды, если Python может выполнять поток отображения.
Последние пять завершённых этапов с длительностями доступны в раскрываемом блоке.
При ошибке индикатор выделяется красным, а исключение остаётся в обычном выводе.

В `<output>/progress.jsonl` записываются начало и окончание **каждого** обучения
и прогноза, подэтап, номер и имя датчика, строки и длительность. Значения
телеметрии туда не записываются. Периодический статус в файле остаётся раз в
15 секунд: обновление экрана не создаёт дополнительных записей таймера.

Родительский этап не публикует свой периодический статус, пока работает вложенный.
После перехода к памяти или проверке надпись «Обработано целей 226/226» не остаётся
ложным описанием текущей операции. Время «Выполняется» относится к названному
подэтапу; `elapsed_seconds` в JSON — ко всему запуску.

При обычном запуске Python вне ноутбука остаётся текстовый журнал. Если интерфейс
обновляемого вывода недоступен, работа продолжается с текстовым выводом и тем же
полным файлом журнала.

## Если снова будет долгая пауза

Последнее сообщение теперь позволяет различить память, упаковку входов, старую
модель, новую модель и сравнение ошибок. У долгого прогноза будет видно конкретный
датчик. Периодический статус сам по себе не доказывает продвижение нативного вызова
CatBoost: он показывает, где этот вызов выполняется.

Количество целей, деревьев, потоки и правила тревог автоматически не сокращаются.
Проверка качества кандидата управляется параметром `validate_candidate`.
Это устранение подтверждённых повторных операций и диагностика задержки; причина
прежних 1500 секунд на конфиденциальной телеметрии пока не установлена.
