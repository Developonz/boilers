# Сравнение классификаторов без регрессора

Откройте `05_Классификатор_без_регрессора.ipynb` в `training` и выполняйте ячейки
сначала. Вспомогательные функции включены внутрь файла: на компьютер с закрытыми
данными достаточно перенести один ноутбук. Если рядом сохранён прежний
`05_Классификатор.ipynb`, его литеральный словарь `DATA_SETTINGS` подхватывается
автоматически. При необходимости переопределите пути в новом `DATA_SETTINGS`.
Чужие ячейки не исполняются. Результаты идут в новую папку
`runs/direct_classifier_comparison`. Новые веса находятся в experiments_v2; прежние experiments не меняются. Прежние корневые таблицы перед первым новым запуском копируются в previous_reports_before_v2.

## Выбор экспериментов

```python
TRAINING_METHODS = ["unit", "group"]
FEATURE_VARIANTS = ["numeric", "numeric_states", "full"]
HORIZONS = [168]                       # либо [24, 72, 168]
ROLLING = {
    "folds": 3, "validation_days": 90, "test_days": 90, "end": None,
    "adaptive_validation": True, "max_validation_days": 730, "validation_step_days": 30,
    "min_train_events": 2, "min_validation_events": 2,
    "min_validation_negative_groups": 2,
}
REPORT_FOLDS = "none"                  # общий результат; latest/all — диагностика
MAX_FEATURE_MATRIX_MB = 2048           # оценка матрицы, не всей памяти Python
```

- `unit`: отдельная модель каждого котла.
- `group`: общая модель котлов одного типа. Используются общие каналы с
  одинаковыми единицами. Однокотловая группа не повторяет `unit`.
- `numeric`: числовые каналы и их 24-часовые признаки, плюс ID котла.
- `numeric_states`: дополнительно состояния и переключения, без длительности
  состояний и времени после пуска.
- `full`: дополнительно длительности состояний и включённое время после пуска.

По умолчанию один горизонт, чтобы не умножать первое обучение втрое. Все выбранные
комбинации перебираются автоматически. План и число попыток показаны перед обучением.
Каждый временной срез — отдельное исследовательское обучение; совместимые готовые
срезы восстанавливаются из кеша. Это не замена боевого ежемесячного обновления.

## Проверка по времени

Тестовые даты остаются фиксированными. Для каждого способа/горизонта validation расширяется
назад от исходных 90 суток шагом 30 суток, максимум до 730 суток: нужны по две независимые
аварии в train и validation и две недельные группы фона в validation. Train находится раньше
validation. Решение об её границах использует только данные до начала test. Для разных
наборов признаков одного сравнения границы идентичны. При невозможности выполнить минимумы
модель пропускается с точными числами и причиной; неподобранный F-порог не подставляется как 0.5.
Тестовые периоды не пересекаются; даты общие для способов, признаков и горизонтов.
Метки прошлого должны быть известны к соответствующей границе. Пересечение
24-часовых входных окон и групп одной аварии между частями исключается.

Период без аварий не удаляется: его ложные положительные учитываются, но AUC/AP
на одном классе не определены. Если подбор порога невозможен, он помечается недоступным и не получает фиктивных метрик. 0.5 остаётся отдельным фиксированным baseline. Если в train один класс
или нет измерений теста, сохраняется конкретная причина пропуска. Конец истории
всех котлов не обрезается по самому короткому. Для более ранних проверок увеличьте
число периодов или задайте `ROLLING.end`; видимое число проверенных периодов
для короткой истории может быть меньше запрошенного.

В сводке Precision/Recall/F объединяют ошибки непересекающихся периодов. AUC/AP
показаны как средние и диапазоны отдельных определимых периодов: шкалы разных
моделей не смешиваются в один общий AUC. Случайный AP сравнивается на тех же
периодах; `rankable_versions` показывает их количество.

## Пороги и два класса

Четыре основных варианта сохранены: 0.5, максимум F1/F2/F0.5 положительного класса.
Дополнительные macro-варианты свёрнуты под стрелку:

`macro Fβ = (Fβ класса 0 + Fβ класса 1) / 2`.

Обычный F тоже штрафует FP через Precision. Macro-F дополнительно даёт равный
вес качеству обоих классов; это критерий выбора порога, а не балансировка данных.
Балансировка и специальные веса по умолчанию выключены.

Дополнительные эпизодные варианты максимизируют событийные Recall или F1
при ограничениях validation:

```python
"alarm_selection": True,
"alarm_persist_hours": 3,
"alarm_merge_hours": 12,
"alarm_budget": 2.0,                    # ложных уведомлений / 720 фоновых часов
"alarm_background_fraction": 0.05,     # доля фона в подтверждённой тревоге
"alarm_candidates": 61,
```

Превышение должно подтвердиться заданным числом часов. Близкие повторные
уведомления подавляются; повторные предупреждения одной аварии не увеличивают
число обнаруженных аварий. Начавшаяся задолго до предаварийного окна тревога
не получает зачёт обнаружения за то, что продолжала гореть. Неизвестные исходы
не становятся ложными тревогами: они учитываются отдельно.

Порог выбирается только на validation. На test ограничения проверяются заново
и могут нарушаться. Если положительных событий для подбора нет или полезного
решения не найдено, результат/ограничение подписывается, возможен вариант без
уведомлений. В бюджетных classification report оценивается подтверждённая тревога,
в обычных и macro — превышение балла без подтверждения.

Для бюджетных вариантов также рассчитывается единая последовательность всех
тестовых срезов с выбранным для каждого среза порогом. Состояние подтверждения и
подавления повторов не сбрасывается при смене модели. Эти показатели начинаются
с `rolling_`; оптимизации по тесту здесь нет.

Baseline включает случайное угадывание, постоянный прогноз по train и «всегда
тревога». Высокий Recall без ограничения ложных тревог не является достаточным
свидетельством полезности.

## Память и вывод

Сначала из контекстов освобождаются большие матрицы, нужные только регрессорам.
Признаки хранятся отдельно по котлам как float32 и только для пригодных часов.
В памяти одновременно одна матрица одного эксперимента, текущие метки и одна
модель. По горизонтам признаки повторно не строятся. Кеш профилей, меток, моделей
и числовых отчётов лежит на диске. Результаты функции обучения — пути и небольшие
таблицы, а не коллекция объектов моделей.

В пункте 7 показаны общие classification report и confusion matrix за всю тестовую
историю каждой модели/котла. Поддержка, ошибки и Precision/Recall/F считаются по всем
непересекающимся тестовым часам. Уведомления рассчитываются одной непрерывной последовательностью,
не сбрасывая подтверждение на границе версии. Отдельные фолды не разбивают основной вывод.
Графики разрываются на остановах и отсутствии измерений, без диагоналей через недели пропусков.
Картинки
встроены как PNG. Большие таблицы скрыты; важность содержит только ненулевые
значения. `REPORT_FOLDS="none"` скрывает картинки отдельных версий; числа
всех периодов всегда остаются в общей таблице. Пункт 7 работает после прерывания
обучения по индексу законченных запусков.

Основные файлы: `experiment_index.csv`, `fold_metrics.csv`,
`comparison_rolling.csv`, `validation_choices.csv`, `selected_models.json`, папка `overall_reports`. Открывать их вручную не нужно.

проверки подтверждают расчёты, причинность и выполнение, а не эксплуатационное качество.


## AUTO и выбор признаков

Все выбранные наборы признаков продолжают сравниваться. Дополнительный вариант AUTO
выбирает набор для очередного будущего теста по AP на одинаковых прошлых validation-часах.
Сверяются подписи временных индексов и меток; при несовпадении автовыбор не выполняется.
При равенстве AP выбирается более простой набор: numeric, затем numeric_states, затем full.
Test-метрики не используются для выбора. AUTO не требует дополнительного обучения: применяются
уже обученные кандидаты. Его общий тестовый отчёт показывает качество всей процедуры выбора.

Последние выбранные модели перечислены в selected_models.json; путь folder указывает
на готовый classifier.joblib/classifier.cbm. Таблица выбора видна в самом ноутбуке.
Если выполнен только один кандидат, это подписано как only_available_candidate.

По предыдущему предоставленному прогону numeric выиграл у full по AP в 35 из 61
сопоставимого случая, full — в 26. Это умеренное преимущество, не общий закон.
На К‑8 и К‑7 перспективны числовые признаки, на К‑2 сильным был full.
После изменения разбиения результаты нужно пересчитать: старые цифры не доказывают качество новых моделей.

Для повседневного просмотра достаточно одного нового 05: функции встроены внутрь.
Для обновления остальных ноутбуков/их библиотек используйте архив обновления.
Для точных результатов нужна телеметрия на рабочем компьютере; локально проверен синтетический запуск.
