# Регрессоры, риск и графики в одном месячном цикле

Актуальное поведение основного ноутбука. Ранее риск добавлялся после раздела 7:
этот порядок заменён. Для автоматического риска достаточно выполнить раздел 3.

## Точный порядок

Для каждой выбранной модели/варианта и группы котлов:

```text
Май:
  1. Обучить/продолжить регрессор К-5 по допустимой истории до 1 мая.
  2. Рассчитать отклонения К-5 за май и причинные признаки.
  3. То же для К-6 и К-7.
  4. Обучить/продолжить общую голову риска 24 ч и голову 168 ч:
     признаки только раньше 1 мая, метки известны не позднее 1 мая.
  5. Получить их оценки для майских точек, сохранить версии и экспорт.
  6. Обновить графики К-5, К-6, К-7 с риском прямо в разделе 3.

Июнь:
  повторить шаги с состояниями предыдущего месяца;
  в риск добавляются только новые уже известные метки и replay старых примеров.
```

Расчёт майских признаков до шага fit не даёт модели будущего: для обучения
выбираются только строки до 1 мая и ответы, доступные к 1 мая. Майские строки
используются только для применения. Непрерывное подтверждение тревог и возраст
эпизода сохраняются через границы месяцев.

При `risk_policy.scope="unit"` вместо общей головы — отдельная для каждого
котла. Разные методы/варианты и физические группы имеют отдельные цепочки.
В pooled конец короткой истории одного котла больше не обрезает месяцы
остальных: общая модель продолжается по доступным источникам. Получатель без
наблюдений в месяце не отправляется в пустой native-predict; это отражается
явным статусом. В transfer ограничение датой наблюдений донора сохраняется.
Тяжёлые native-fit идут последовательно: это общее помесячное расписание,
не несколько конкурирующих тренировок в потоках.

## Дообучение классификатора

Первый fit запускается, когда в пригодных примерах впервые есть необходимые
независимые группы обоих классов. Он использует доступную обучающую часть
прошлого. Затем прежние деревья продолжаются новыми: стандартно первоначально
150, добавление 20, предел 1500; параметры общие `cb_*`.

Сохраняются постоянный групповой резерв калибровки и replay. Без новых меток
деревья не добавляются. При достижении предела сохраняется предыдущая модель
и явный статус. Пересмотр прошлых входов/меток или несовместимость схемы требуют
явного пересоздания — старые деревья не умеют забывать ошибочные примеры.
**Финального fit на всей итоговой истории в стандартном ноутбуке больше нет.**

У каждой месячной головы сохраняются `fit_status`, `trees`, `new_training_rows`,
дата доступности и максимальная дата использованной метки. Это видно в таблице
готовности. Минимумы событий не понижены: две аварии и две фоновые группы в
обучении; для процентов дополнительно две группы каждого класса в калибровке,
после защитных исключений. Без калибровки доступен балл, а не процент.

## Где графики и настройки

Под ячейкой **раздела 3** отдельные обновляемые карточки моделей и котлов:
месячные срезы, текущие датчики/этап, прежний двухпанельный график, риск на
тревогах, готовность и Precision. Предыдущие карточки остаются на месте.

В ячейке настроек:

```python
INTERPRETATION = {"run": True, "as_of": None, "attach": True}
LIVE = {
    "enabled": True, "update_every_months": 1,
    "show_risk": True, "view": "mean::instant", "budget": None,
    "start": None, "end": None,
}
```

- `run=True` включает месячное обучение риска уже в разделе 3;
  False оставляет детекторы, риск получает `not_run`.
- `attach=True` добавляет готовую голову в текущий и соответствующий
  месячный экспорт. Её дата доступности остаётся настоящей, а не датой
  последующего открытия отчёта.
- `as_of=None` разрешает обновления по всему расписанию. Явная дата
  ограничивает знания для fit: после неё новые ответы не обучают голову.
- `LIVE` управляет только отображением. `show_risk=False` скрывает подписи,
  не отключает обучение. Старое имя `risk_history` принимается как его алиас;
  прежний смысл «отдельный расчёт в разделе 7» больше не действует.

Пользователю **не нужно создавать LiveReport/LIVE_REPORT**. Новый вызов:

```python
RESULT = LF.run(CFG, live_options=globals().get("LIVE", {}),
                interpretation=globals().get("INTERPRETATION"))
```

Объект вывода создаётся внутри функции и доступен при необходимости как
`RESULT["live_report"]`. Для старых импортов сохранён алиас `LiveReport`.
Обновляйте всю папку lib вместе с ноутбуком, затем перезапускайте ядро.

Раздел 7 читает сохранённый помесячный риск и отдельно обрабатывает проверенные
метки причин. Повторный раздел 7 не запускает полный fit риска. Если раздел 3
не был выполнен новым кодом, будет `requires_monthly_training`.

## Precision

На графике и в основных сравнениях:

```text
precision = полезные уведомления / (полезные + фоновые уведомления)
```

Полезное — уведомление в интервале от `pre_window_days` до `min_lead_hours`
перед зарегистрированной аварией. Фоновое — уведомление на оцениваемом рабочем
фоне с полностью наблюдаемым будущим на длину pre_window_days. Неизвестные
остановы, нейтральные участки и неполное будущее не объявляются ложными.
Для будущей наблюдаемости используется нагрузка, а не наличие прогнозов.
Счётчик всех фоновых уведомлений описывает нагрузку на оператора и может быть
больше знаменателя Precision: для части последних уведомлений исход ещё
неизвестен. Число исключённых случаев выводится отдельно. Precision детектора
оценивается ретроспективно по имеющемуся реестру, метрики риска — по исходам,
уже известным к указанной дате оценки.

Например, 2 полезных и 3 фоновых уведомления дают Precision 40%. Если из трёх
аварий пойманы две, Recall 67%. Число пойманных аварий не подставляется вместо
числа полезных уведомлений: перед одной аварией их может быть несколько.
При нулевом знаменателе показывается «—», а не 100%.

В CSV есть `precision_true_notifications`, `precision_false_notifications`,
`precision_excluded_notifications`, отдельно неполное будущее. Для сравнения
с прежним способом добавлен `episode_precision` по активным эпизодам:
повторные эпизоды и подавление уведомлений делают эти два показателя разными.
Это связь с зарегистрированными авариями, а не доказательство причины поломки.

Для классификатора риска отдельно считаются Precision/Recall ранее выданных
помесячных прогнозов на точках, чей исход уже известен на текущий fit_date.
Это **не ответы только что обученной головы на её train**. Балл и вероятность
оцениваются раздельно при пороге `risk_policy.confidence` (по умолчанию 0.7).
В `risk_metrics.csv` указаны число точек, независимых положительных событий,
граница доступности меток, область/котлы. Эти точки могут быть зависимы;
Precision по нескольким авариям не доказывает надёжную вероятность.

## Что сохраняется и восстанавливается

- `monthly_risk/<семейство>/<дата>/risk_*h/` — каждая голова, статус,
  `fit_signature.json`, feature importance. Проверяется и предшествующая
  версия цепочки: изменение раннего fit не оставляет поздние кеши незаметно.
- `model_history/<месяц>/risk_*h.joblib` и `model/risk_*h.joblib` — головы
  внутри экспортов при attach=True; все файлы входят в манифест.
- `risk_timeline.parquet`, `risk_metrics.csv`, `classifier_readiness.csv`,
  `training_plot.png`, `alarm_risk.csv` — результаты в папке получателя.
- `risk_status.csv`, общая `classifier_readiness.csv`, `progress.jsonl` —
  текущее состояние всего запуска в корне output.

Если процесс остановлен после обучения одного горизонта, завершённая голова
восстанавливается по подписи. Незавершённая голова учится заново; прогресс
деревьев внутри одного незавершённого fit не сохраняется. История прогнозов
восстанавливается при проходе уже готовых месячных состояний без нового fit.

Регрессоры контракта 4 не требуется заново обучать ради этого изменения:
их checkpoints и оценки месяцев восстанавливаются. Новая месячная цепочка
классификаторов строится один раз; старую итоговую голову, обученную позднее,
нельзя выдавать за ранние месячные версии.

## Дополнительные исправления

Категориальные значения теперь явно переводятся в StringDtype до заполнения
пропусков. Предупреждение pandas о неявном downcasting устраняется в причине,
без глобального подавления предупреждений. Формат категорий и NaN-метка
сохранены. Поправлены типы пустых таблиц feature importance у методов без
нативной важности и чтение пустых необязательных отчётов. Реестр models.csv
повторяет атомарную замену при кратком Windows-lock; сами веса сохраняются
раньше обновления этого списка.
