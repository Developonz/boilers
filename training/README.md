# Обучение и диагностика

Полная инструкция: [ИНСТРУКЦИЯ.md](ИНСТРУКЦИЯ.md) — запуск по шагам, все параметры
и начальные значения, автоматические результаты, разметка и продолжение с новым месяцем.

Основной ноутбук `02_Обучение.ipynb` использует новый последовательный конвейер:
аудит режимов, правила качества датчиков, настоящее месячное обновление моделей,
средние по доступным датчикам и интерпретация эпизодов. Выполните **Run All**:
проверки, обучение и отчёты запускаются ячейками, отдельные скрипты запускать не нужно.
Пути, пороги, правила датчиков и дополнительные исследования настраиваются в первом
блоке ноутбука; проверенные метки эпизодов сохраняются из отдельной ячейки.
Реестр событий, графики режимов, сравнение моделей и тревог, результаты интерпретации
выводятся под соответствующими ячейками. Файлы результатов сохраняются автоматически.
Подробности, ограничения и необязательные команды: [docs/INCREMENTAL.md](docs/INCREMENTAL.md).

Предыдущий вход сохранён как `02_Обучение_legacy.ipynb`; выполненные результаты не менялись.
Ниже сохранено описание прежнего конвейера для воспроизводимости сравнения.

## Legacy 2.2: прежние модели, пакетная проверка групп

Откройте **02_Обучение.ipynb** и выполняйте сверху вниз. В настройках задайте CFG:
группы, сценарии, методы и пути. UNIT и главный котёл не нужны.
Таблицы и графики находятся в самом ноутбуке, с раскрывающейся навигацией без виджетов.

```python
CFG.update(
    GROUPS={'Группа 1': ['К-1', 'К-2', 'К-3', 'К-4'],
            'Группа 2': ['К-5', 'К-6', 'К-7'], 'Группа 3': ['К-8']},
    SCENARIOS=['local', 'pooled', 'transfer'],
    MAIN_METHODS=['analogs', 'AAKR', 'MSET'],
)
```

- local: отдельная модель каждого котла. LOCAL_SENSOR_SETS=['common', 'full']
  проверяет общий набор группы и отдельно собственные датчики котла.
- pooled: одна модель на истории группы, проверка каждого котла.
- transfer: каждый донор по отдельности → остальные котлы группы.
  TRANSFER_DONORS=None — все; можно задать словарь «группа → доноры».
- Одиночная группа: индивидуальная проверка; остальные сценарии неприменимы.
  Пустая история одного донора не запрещает использовать достаточную историю других.

sensor_roles.xlsx задаёт датчики, условия, состояния и нагрузку. При объединении
и переносе используется пересечение параметров всей группы, включая небаланс
пар/вода. Формула после названия небаланса и смешанные KA/КА не влияют на поиск.
Рабочая таблица ролей находится в этой папке.

OTHER_METHODS: Регрессия, Близнецы, AAKR (все датчики), MSET (все датчики),
Остатки analogs, Остатки AAKR, Остатки MSET, Остатки регрессии.
Вторые ступени RESIDUAL_METHODS: PCA, Махаланобис, Isolation Forest, AE, LSTM.
AE/LSTM требуют уже существующего окружения TensorFlow; установки из ноутбука нет.

Основные метрики: PR AUC и его случайный уровень, Precision, Recall, F1, тревоги в фоне в месяц,
процент фона в тревоге, упреждение. Ранг и p исключены из рабочего отчёта.
THRESHOLD_MULTIPLIERS задаёт отдельную таблицу порогов без переобучения.
Плавная близость к останову — самостоятельная экспериментальная таблица.

Основной режим `TRAIN_UPDATE='fast'`: первый месяц — прежние 3 OOF-блока и итоговая
модель, дальше — ошибки новых часов от предыдущей модели и одно обучение на текущем
окне истории. Старые ошибки вне актуального обучающего окна удаляются. Параметры и
реализации основных моделей прежние; калибровка порогов меняется, метрики могут отличаться.
Это не эквивалентный partial_fit. При изменении доступности датчиков или недостатке
ошибок для калибровки выполняется новый OOF-старт.

`TRAIN_UPDATE='refit'` — прежний расчёт 3 OOF-блоков каждый месяц. Для чистого
сравнения отключите `IMPORT_LEGACY_CACHE` в обоих режимах. Результаты и модели
сохраняются отдельно в экспериментах с суффиксами `__fast` / `__refit`.
Быстрое обновление применено к analogs/AAKR/MSET (включая «все датчики»), регрессии,
близнецам и первой ступени остатков. Вторые ступени остатков, AE/LSTM — прежнее обучение.

С 2.2 фильтры датчиков используют только текущие и предыдущие значения:
скачки сравниваются с прошлыми приращениями за CLEAN_WINDOW_H=168 ч (минимум
CLEAN_MIN_HISTORY_H=24 ч, коэффициент CLEAN_SPIKE_FACTOR=8). Залипание отмечается
после CLEAN_FROZEN_H=24 ч без ретроспективной маскировки начала участка.
Экспорты содержат те же фильтры. Историческое определение режимов работы сохранено.

Кэш моделей/оценок 2.0/2.1 с прежней очисткой несовместим: импорт отключён.
Новые результаты и экспорты — в экспериментах с __v22__, старые файлы остаются.
RECOMPUTE=False продолжает уже текущий расчёт 2.2, не старые модели.
Отчёт фиксируется после каждого эксперимента; LF.load_report(CFG) восстанавливает готовую часть.
VERBOSE=False оставляет группу, котёл, метод и итоги по времени/часам/обучениям/экспорту.
VERBOSE=True включает помесячные подробности. SHOW_PROGRESS_RESULTS=False убирает
повтор промежуточных графиков перед финальными разделами ноутбука.

Графики возвращены из прежнего ноутбука: суточный максимум, две панели,
серые простои, прежние цвета аварийного/планового ремонта и резерва, полоса
«котёл / тревога», прежняя легенда и метрики в заголовке. Сохранена только новая
шкала оценок: линейная до 1, сжатая выше, без обрезки пиков на 5.
LF.show_period(RESULT, **DETAIL_PERIOD) показывает выбранные даты без обучения;
тревоги не перестраиваются, метрики в заголовке остаются за полный период.
В таблицах видны количества полезных/фоновых/нейтральных эпизодов и часы проверки/фона.
Процент фонового времени в тревоге выводится как процент, остальные PR/Precision/Recall — доли.

Если у котлов разные названия каналов расхода пара с ролью «нагрузка»,
`ALIGN_LOAD_ROLE=True` сопоставляет их по назначенной роли; исходные имена остаются
в аудите. Проверяются название физической величины и заявленные единицы.
Так исправлено отсутствие общего канала нагрузки К-3 в группе К-1–К-4.
Роль не гарантирует тождество разных физических точек: корректность выбора проверяет технолог.

Для основных моделей при недостатке обучения берётся предыдущая успешная модель,
с указанием фактической даты обучения. Экспорт истории не обучает пропущенные месяцы:
`HISTORY_MISSING='previous'` берёт предшествующую модель, `'skip'` пропускает месяц.

Ночной запуск из этой папки:

```powershell
python run_overnight.py --check-only
python run_overnight.py
python run_overnight.py --config my_settings.json
```

JSON содержит имена параметров CFG без обёртки CFG. Выполненный ноутбук
с таблицами и встроенными изображениями — runs/02_executed.ipynb.
--check-only проверяет план, пути и таблицу ролей без обучения.

Файлы:

- 02_Обучение.ipynb — настройки, запуск, таблицы, графики, навигация.
- 02_Обучение_результаты.ipynb — ваш выполненный прогон с сохранёнными выводами, без изменений.
- 03_Проверка_сохранённой_модели.ipynb — применение экспорта к выбранному котлу.
- lib/legacy_core.py — исходный код алгоритмов из прежнего ноутбука.
- lib/legacy_fleet.py — перебор экспериментов и отчёт.
- lib/legacy_metrics.py — метрики и пороги.
- lib/legacy_group.py — роли, объединение историй, кэш, экспорт.
- lib/legacy_cleaning.py — каузальные фильтры датчиков; lib/legacy_plots.py — графики.
- lib/k2_lib.py, kernel_models.py, k2_deploy.py — прежние реализации моделей.
- data_tools/ — подготовка данных; docs/ — методика; tests/ — проверки.
- Прежние сборки и служебные прогоны вынесены в резервную копию в Downloads; путь указан в корневом README.

Модели: models_legacy/<группа>/<эксперимент>/<котёл>/<метод>/final/ и папки
ГГГГ-ММ. Исторические экспорты задаются HISTORY_FOR. Отчёт восстанавливается
через LF.load_report(CFG) после подключения lib; полный отчёт — anomaly_results_legacy/fleet_report.joblib.

Для переноса используйте папку legacy. При необходимости исключите результаты
своих прогонов. Телеметрия в комплект не входит. Подробности: docs/ПОДРОБНО.md.

В fast последовательность месячных обновлений сохраняется и через месяцы без проверки
конкретного котла: необходимые промежуточные модели готовятся перед следующим обновлением.
Это сохраняет одинаковую цепочку при проверке разных получателей общей модели.
Экспорт истории сам обучение не вызывает. Дата начала проверки входит в ключ fast-кэша.

Для воспроизводимой очистки при применении экспорта передавайте доступную предысторию.
В ноутбуке 03 оставьте WARMUP_HOURS=None (вся доступная история).
